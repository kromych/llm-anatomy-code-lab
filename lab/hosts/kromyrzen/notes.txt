OPEN QUESTIONS / DECISIONS FOR THE AUTHOR
1. The book's `winget install llama.cpp` and `winget install Ollama.Ollama` could not be tested over key-auth SSH. Testing them
   needs an interactive logon (console or RDP) as labuser, or approval for a workaround such as `winget source reset --force`.
   Also note that the winget llama.cpp package is the Vulkan build. On this GPU Vulkan should find no device, but that is untested.
2. Ollama's intended post-install state (tray app running, Startup\Ollama.lnk created by the app on first run, and any WebView2
   UI data under %LOCALAPPDATA%\Ollama) needs an interactive logon. Someone needs to sign in as labuser, start Ollama once from
   the Start Menu and then take another snapshot.
3. llama-server b12359 defaults to port 9931, but the brief and the krom1u notes say 8080. Check the book text and the Mac
   observation; did the Mac test pass --port, or use another build?
4. The HF cache snapshot entry is a symlink, created here with admin rights. Behavior for a standard user without Developer
   Mode is untested.
5. The llama.cpp zip route leaves llama-server off PATH. I did not add it to PATH, because that would be a manual
   environment change, not an installer action.
